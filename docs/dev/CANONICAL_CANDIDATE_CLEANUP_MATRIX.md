# Canonical Candidate State Cleanup Matrix

**Issue:** [#211 — Candidate state cleanup](https://github.com/RayZhang2024/Career-trans/issues/211)

**Audit base:** `7d27a38a90233673495025268b81fc244c867357` (live `origin/main`, PR #219 merge)

**Phase:** 1, static inventory and deletion classification only
**Search scope:** tracked repository files at the audit base; untracked scratch files were excluded.

This is a point-in-time caller and data-dependency audit. No production behavior is changed in this phase. A `REMOVE` or `MIGRATE_THEN_REMOVE` label is a future recommendation, not a deletion authorization.

## Classification key

- **REMOVE** — no runtime caller/data dependency remains after the stated cleanup; remove in the planned phase.
- **MIGRATE_THEN_REMOVE** — live callers must first be moved to the named replacement and verified against the listed semantics.
- **RETAIN** — still has a distinct authority, domain, compatibility, API-safety, or historical purpose.
- **UNCERTAIN** — the inventory is insufficient to safely decide; resolve the listed question before cleanup.

The two tombstone routes receive the more specific sub-decision `RETAIN_AS_SAFETY_TOMBSTONE`, mapped to the matrix classification `RETAIN`.
