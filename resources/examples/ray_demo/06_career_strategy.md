# Career Strategy

## Purpose

This document defines the strategic direction Career Agent should use when deciding not only whether the candidate can obtain a job, but whether the job is worth pursuing.

---

# 1. Core Career Objective

Build a career at the intersection of:

- engineering;
- software;
- artificial intelligence;
- data;
- technical problem solving;
- customer-facing delivery;
- high-value industrial applications.

The desired long-term identity is not purely:

> scientist

or purely:

> software engineer

but rather:

> a technically deep problem solver who can understand complex customer/engineering problems and build or deploy software, data, and AI solutions to solve them.

---

# 2. Career Transition Principle

The preferred transition is evolutionary rather than a complete reset.

Career Agent should prioritise roles that allow existing strengths to remain valuable while increasing exposure to:

- production software;
- AI;
- data;
- cloud;
- products;
- customers;
- commercial delivery.

This reduces the risk of competing only as an entry-level software engineer.

---

# 3. Strategic Positioning

For AI / software roles, the desired market positioning is:

> An experienced technical professional already using software, automation, data, and AI to solve real engineering problems.

Avoid positioning as:

> A scientist with no software background trying to become an engineer.

---

# 4. Priority Role Families

## Tier 1 — High Strategic Interest

### AI Solutions Engineer

Why:

- combines AI and software with customer problem solving;
- benefits from technical communication and industrial experience;
- provides production AI exposure;
- strong fit with current trajectory.

### Forward-Deployed / Deployed Engineer

Why:

- strong match to problem-solving and customer-facing background;
- rewards ability to operate across domain, software, data, and implementation;
- creates strong career capital.

### Applied AI Engineer

Why:

- builds directly on current LLM / agent work;
- increases production AI credibility;
- strong future marketability.

### Scientific Software / Engineering Software Engineer

Why:

- leverages existing scientific/engineering depth;
- provides a lower-risk bridge into stronger software engineering;
- can be especially attractive where domain knowledge matters.

### Technical Solutions Engineer

Why:

- matches customer-facing technical problem solving;
- can leverage engineering/science expertise while increasing software exposure.

---

## Tier 2 — Attractive Depending on Role

### Data / AI roles in finance

Strategic value:

- high compensation potential;
- strong data/AI career capital;
- interesting transition path.

Risks:

- finance-domain gap;
- some roles require stronger statistics, markets, data engineering, or software depth.

### Technical Product / Implementation roles

Attractive when sufficiently technical and hands-on.

Avoid roles that become mainly administrative project coordination with little technical growth.

### Advanced Engineering / Structural Integrity

Very strong current fit.

Best when role includes:

- digital engineering;
- simulation;
- AI/data;
- technical leadership;
- strong compensation;
- strategic responsibility.

Less attractive if it reinforces only the existing specialism without new career capital.

---

# 5. Lower Strategic Priority

Roles should be deprioritised when they are predominantly:

- narrow academic research;
- repetitive experimental work;
- purely operational laboratory work;
- routine project administration;
- highly specialised residual-stress work with little growth outside the current niche;
- generic junior software roles that discard previous experience;
- roles with limited technical ownership.

These are not automatically bad jobs, but may have lower strategic value.

---

# 6. Job Evaluation Framework

Every job should receive at least two separate assessments.

## A. Current Fit Score

Question:

> How likely is the candidate to perform and credibly obtain this job today?

Consider:

- essential requirements;
- technical skills;
- experience;
- seniority;
- domain knowledge;
- customer skills;
- leadership;
- location / work authorisation;
- hard blockers.

## B. Career Alignment Score

Question:

> If the candidate gets this job, how much does it improve their future position?

Consider:

- AI exposure;
- software engineering growth;
- production responsibility;
- cloud exposure;
- customer ownership;
- technical depth;
- future salary potential;
- marketability;
- leadership potential;
- industry attractiveness;
- portability of skills.

---

# 7. Recommended Decision Matrix

| Fit | Career Alignment | Typical Decision |
|---|---|---|
| High | High | APPLY — priority |
| Medium | High | APPLY — strategic stretch |
| High | Medium | APPLY selectively |
| High | Low | Consider opportunity cost |
| Medium | Medium | CONSIDER |
| Low | High | Usually build gaps first unless requirements are flexible |
| Low | Low | SKIP |

The agent should not mechanically apply this table if there is a hard blocker.

---

# 8. Career Capital

Career Agent should explicitly identify what each job adds.

Examples:

- production Python;
- React;
- cloud;
- enterprise AI;
- customer deployment;
- financial markets;
- leadership;
- security clearance;
- product ownership;
- large-scale systems;
- data engineering;
- commercial responsibility.

A role that adds scarce career capital may be worth pursuing despite a moderate current fit.

---

# 9. Opportunity Cost

Job recommendations should consider the cost of spending time on an application.

Prefer:

- fewer strong applications;
- strategic stretch roles;
- companies with meaningful learning/value;
- roles where the candidate has distinctive evidence.

Avoid mass applications with weak fit and low strategic value.

---

# 10. Short-Term Development Strategy

## Next 6–12 Months

Strengthen evidence that the candidate is a software/data/AI practitioner.

Priority evidence-building projects:

1. Build a production-style Career Agent web application.
2. Build React frontend capability.
3. Build FastAPI backend capability.
4. Implement authentication and multi-user architecture.
5. Deploy a real application.
6. Add database persistence.
7. Add testing and CI/CD.
8. Continue NEAT AI integration where possible.
9. Demonstrate evaluation and observability.
10. Build visible portfolio evidence.

This should shift market perception from:

> scientist learning AI

toward:

> engineering/data/AI practitioner with real delivery experience.

---

# 11. Long-Term Optional Paths

Potential future directions include:

### Path A — AI / software
Applied AI -> Solutions / Deployed Engineering -> senior AI/technical leadership.

### Path B — Finance
Data/AI role -> trading/investment data and AI -> higher-value finance technology roles.

### Path C — Engineering technology
Advanced engineering -> digital engineering / AI / simulation leadership.

### Path D — Technical product / consulting
Solutions -> technical product / consulting / customer engineering leadership.

---

# 12. Recommendation Behaviour

Career Agent should:

- challenge low-value applications;
- identify strategic stretch opportunities;
- explain why a role is valuable;
- distinguish missing evidence from missing capability;
- identify what can be learned before applying;
- identify hard blockers early;
- avoid over-weighting job-title similarity;
- recognise unconventional but credible transitions.
